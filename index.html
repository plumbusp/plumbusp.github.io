Predicting Winners in the Eurovision Song Contest

By Tim Kicker, Yauheni Zviazdou, Anna-Ilona Nikolaeva

Motivation

Since 1962, every year European coutry gather together together to compete for the best song. Eurovision is in the center of attention each ... and betting markets start booing around that time with predictions of winners.

But are we aware of who should win statistically? In this project we analized previoous Eurovion competetions to try to get valuable insights on trends, crowd and jurys' favorites, and general statistics that define winners.

We wanted to benefit prediction market users to make smarter bets, as well as provide insights for competing Eurovision artists on what are theit statistical advntages/disadvatages.

we also wanted to explore how shared borders and langugaes between countries influnce votings.

Dataset description

One row is one directed pair in one contest: who gives, who receives, how many points, jury or televote. Finals only, 2016 to 2026 (2020 was cancelled).

19,800pair rows
10contests
2vote types

Sources

  • Votes and entries: the Spijkervet Eurovision dataset up to 2023, eurovisionworld.com from 2024.
  • Country relationship: CEPII GeoDist, with distance, shared border, shared language and colonial ties.
  • Past points: all voting history since 1957, used only to say how much two countries liked each other before.
  • Attention: Google Trends, per voting country, for the artist and the song, cut the day before the final.
  • Lyrics: sentiment, repetition and theme of each song.
  • Artists: age and sex from Wikidata.

We deliberately do not use YouTube views. They are only available as of today, so a winner would get views it earned because it won.

The song (the entry itself) explains 25 % of the jury points and 40 % of the televote points. The relationship between countries explains four times more for the public than for the jury. Juries judge the song. The public also votes for its friends.

Strongest friendships

Points given beyond what the song earned, at least three meetings: Greece to Cyprus +10.5 and North Macedonia to Albania +10.4 in the televote, Montenegro to Serbia +9.8 in the jury.

Can we forecast the ranking?

We predict each year without ever seeing it, and measure how far off the predicted place is. Random guessing is off by 8.4 places.

With relationships plus search interest we beat the published reference (6.07 for audio, lyrics and YouTube views together) in the televote, using only data that exists the day before the final.

Our win probabilities are not reliable, so we do not show them.

Technical background

Pipeline

Python 3.12, pandas and DuckDB, Parquet on disk, scikit-learn and statsmodels. The whole pipeline runs offline from cached downloads:

uv run esc data     # download and cache sources
uv run esc parse    # raw files to typed tables
uv run esc build    # join to the pair panel
uv run esc model    # forecast and explanation
uv run esc all

Two modes

Forecast: ridge, gradient boosting and random forest, leave-one-year-out cross-validation. A whole contest is held out each time, so nothing leaks from the future. Features: distance, border, language, colonial ties, past points and Google Trends. Metric: mean distance between predicted and actual place, against a chance baseline from simulations.

Explanation: a ridge regression splits the explained variance into entry only, relationship only and overlap. The entry part uses the receiver effect, which is what all other countries gave the same entry. That makes it explanatory, never a forecast.

Design decisions

  • Pairs that gave zero points stay in the data as zero. Otherwise only successes remain and every coefficient is biased.
  • Entry-level features such as lyrics and running order made the trees worse. Within a year they identify the entry, so the trees memorise it.
  • Semi-final results are published only after the final, so they are never used.
  • Everything is seeded and sorted, so a rerun gives byte-identical files.

Example: leave-one-year-out

for year in years:
    train = panel[panel.year != year]
    test = panel[panel.year == year]
    model.fit(train[features], train["points"])   # imputation median from train only
    test["pred"] = model.predict(test[features])

Future improvements

  • Audio features. The published baseline uses the sound of the song, which we have not added.
  • Better entry features. Lyrics and running order did not help the trees. A model that handles entry-level features properly might.
  • More Trends coverage. Bosnia is missing, so 52 panel rows have no search data.
  • Calibrated win probabilities. Entries with a predicted chance above 50 % won only one time in eight. The model needs recalibration before we can show them.
  • More history. Only ten contests have separate jury and televote data. Every new contest adds 2,000 rows.
  • Semi-finals. After the contest, their points could be added to the explanation.
